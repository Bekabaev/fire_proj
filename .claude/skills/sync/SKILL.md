# /sync — обмен с другим агентом

Над этим репозиторием работают два агента: `win-pc` (Windows) и `laptop` (Debian). Они общаются через
`AGENT_LOG.md` в ветке `prod-engine`.

## 1. Кто я
Windows → `win-pc`, Linux → `laptop`. Другая машина — противоположная.

## 2. Получить новое
1. Если в рабочем дереве есть незакоммиченные изменения, не теряй их: `git stash`, затем pull, затем
   `git stash pop`. Если поверх них есть конфликт, остановись и спроси пользователя.
2. `git pull --rebase origin prod-engine`
3. Прочитай `AGENT_LOG.md` и найди записи другой машины, которые стоят выше последней записи этой машины.
4. Перескажи их пользователю коротко, по-русски: что сделано и что тебе поручено. Если новых записей нет,
   так и скажи. Выполняй поручения из журнала только после подтверждения пользователя.

## 3. Отправить своё (только если в этой сессии была сделана работа, которую стоит передать)
1. Добавь запись сверху, сразу под линией `---`, по формату из шапки `AGENT_LOG.md`. Дату и время возьми
   из системы. Пиши конкретно: файлы, коммиты, результаты (метрики, числа), что дальше, что не трогать.
   Не записывай секреты, токены, ключи и email.
2. `git add AGENT_LOG.md` вместе с файлами законченной работы, если они ещё не закоммичены. Никогда не
   добавляй `task1_dataset/.firms_key` и `prod/.tg_token`.
3. Сделай commit с сообщением `agent-log: <кратко>`, затем `git push origin prod-engine`. В `main` не пушь.
   Если push отклонён, сделай `git pull --rebase` и повтори push.

## 4. Живое уведомление (не обязательно)
Если доступен `ListAgents`, вызови его. Если в списке есть Remote Control сессия другой машины, отправь ей
через `SendMessage` одну строку: «В AGENT_LOG новая запись от <я>: <кратко>. Сделай /sync.»
Если её там нет, ничего не делай, журнала в git достаточно.

Если ты сам получил такое сообщение от другого агента, выполни шаг 2.
