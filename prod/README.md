# prod — движок прогноза и симуляции степных пожаров для сайта

Сетка 500 м (EPSG:6933), сцена 96 × 96 ячеек (48 × 48 км) вокруг пожара, горизонты 12 / 24 / 48 / 72 ч,
дольше 72 ч — прокрутка шагами по 24 ч (окно сдвигается за пожаром).

## Модель
Гибрид (task2 шаги 19–21):
- **U-Net FrontV3 с погодой** (`out_v3/wx_best.pt`) — где и сколько сгорит по данным (обучен на 43,6 тыс. срезах GFA + VIIRS 2013–2021);
- **физика FBP O-1b + эллипс по ветру** (`task2_model/scripts/sim_physics.py`) — направление и порядок выгорания, барьеры, склон;
- **стекинг** по ячейкам на каждом горизонте: `logit p = a·logit(p_unet) + b·log(T/h) + c·[недостижимо] + d·log(T/h)·ветер + e`,
  изотоническая калибровка и порог по val 2022 на прогнозе GFS (`out_v3/prod_hybrid.json`, блок `deploy`).

Почему гибрид: в обучающих метках (GFA/VIIRS) связь направления роста с ветром слабая (cos 0,10–0,14), и U-Net воспроизводит
ровно её; на экспертных метках заповедников связь втрое сильнее (cos 0,38). Физика добавляет направление ветра, которого
ждут пользователи симулятора, U-Net — площадь и места, где огонь реально идёт.

## Входы
| Что | Откуда | Прод |
|---|---|---|
| Растительность, рельеф, дороги/посёлки | `task1_dataset/data/ext_kz/{lc,dem,osm}.npz` | статично |
| NDVI до пожара | `ndvi_<год>.npz` 2012–2026 (MOD13A1; 07–10.2025 нет в каталоге → норма + аномалия, флаг `ndvi_stale_days`) | обновлять `task1 шаг 12 ONLY_YEARS=<год>` |
| Прошлые гари | `doy_<год>.npy`: GFA до 2024, MCD64A1 2025–26 (task1 шаг 36; 05, 08–10.2025 — термоточки FIRMS, шаг 37), `last_burn_<год>.npy` | обновлять `шаг 36 burns/fuel` (данные MCD64A1 — с задержкой ~2 мес., флаг `burns_known_until`) |
| Погода | Open-Meteo: прогноз GFS (`gfs_seamless`) + архив ERA5 (прошлые 7 сут, FWI) | онлайн, без ключа |
| Состояние пожара | маска гари (точки lon/lat), термоточки FIRMS (lon, lat, часов до t, FRP) или круг вокруг точки | от сайта / FIRMS NRT |

FWI считается по полуденным значениям ERA5 + GFS (`task1_dataset/scripts/fwi.py`), в обучении — NASA GFWED.

## Запуск
```sh
cd project_till_nov
../.venv/Scripts/python.exe -X utf8 -m uvicorn prod.server:app --host 0.0.0.0 --port 8000
../.venv/Scripts/python.exe -X utf8 -m prod.checks          # приёмочные проверки -> prod/checks_report.json
```
API: `GET /health`, `POST /predict`, `POST /simulate` — форматы запросов в `server.py`. Ответ — контуры GeoJSON (lon/lat) по горизонтам
или по кадрам каждые 12 ч, площади, использованная погода; `grids: true` — ещё растры вероятности (u8) и времени прихода огня
с углами окна для наложения на карту.

Из Python:
```python
from prod.engine import FireEngine
E = FireEngine()
r = E.simulate(lon=64.4, lat=51.5, hours=120, weather={"winds": [8, 270], "T": 32, "RH": 15})   # ветер 8 м/с с запада
r = E.predict(lon=64.4, lat=51.5, radius_km=2, t_utc="2026-07-20 06:00")                      # прогноз GFS
```

## Ресурсы
U-Net 541 тыс. параметров — CPU ≈ 0,1 с на сцену, физика ≈ 1–3 с; национальные слои ≈ 1 ГБ в памяти.
